# แผน: ทำการสลับเมนูและการแสดงหน้าให้ลื่นขึ้น

## เป้าหมาย
กดเปลี่ยนเมนูล่าง (หน้าแรก / แดชบอร์ด / โทร / ตั้งค่า) แล้วหน้าเปลี่ยนแบบนุ่มนวล ไม่กระตุก ไม่แวบขาว ไม่เด้งทันทีแบบแข็ง ๆ

## สิ่งที่จะทำ

### 1. แอนิเมชันตอนเปลี่ยนหน้า (TabLayout)
- ครอบเนื้อหาหน้าใน TabLayout ด้วยชั้นที่มี key ตาม `location.pathname`
- ทุกครั้งที่เปลี่ยนเมนู หน้าใหม่จะ **ค่อย ๆ จางเข้า (fade-in) พร้อมเลื่อนขึ้นเล็กน้อย (~8px)** ประมาณ 200ms ด้วย CSS animation ล้วน ๆ (ไม่เพิ่มไลบรารี)
- ใส่ keyframe ใน `src/index.css` (เช่น `page-enter`) และคลาส `animate-page-enter` ใช้ซ้ำได้

### 2. แถบเมนูล่างเปลี่ยนสถานะแบบนุ่ม (BottomNavigation)
- ปุ่มที่ถูกเลือก: พื้นหลังไฮไลต์ไล่สี + ไอคอน/ตัวหนังสือ เปลี่ยนสีแบบ **ค่อย ๆ เปลี่ยน (transition 180–220ms)** แทนการสลับทันที
- เพิ่ม `transition` ให้กรอบไฮไลต์ ไอคอน และตัวหนังสือ (ใช้ inline style transition ตามโครงเดิมของไฟล์)
- เพิ่ม feedback ตอนกด: ปุ่มยุบลงเล็กน้อย (scale 0.95) ขณะแตะ แล้วคืนตัว — ให้ความรู้สึกตอบสนองทันที

### 3. ลดอาการแวบตอนโหลดหน้า
- ช่องโหลดของแท็บ (TabContentLoader) ให้จางเข้าแบบเดียวกัน ไม่เด้งขึ้นมาทันที
- ยังคง preload หน้าทุกเมนูไว้ล่วงหน้าเหมือนเดิม (ทำไว้แล้ว) ทำให้แทบไม่เห็นช่องโหลดเลย

### 4. หน้าอื่นที่ไม่ใช่เมนูล่าง
- ใช้แอนิเมชันจางเข้าแบบเดียวกันกับหน้ารอง (รายละเอียดงาน ฯลฯ) ผ่าน Suspense หลัก เพื่อให้ทั้งแอบรู้สึกสม่ำเสมอ

## ไม่แตะต้อง
- ลำดับเมนู ไอคอน สีหลัก และข้อความเมนูเดิม
- flow งานทั้งหมด (เช็คอิน / SOP / POD / สแกน QR / คิว)
- ระบบ preload และแคชข้อมูลที่ทำไว้แล้ว

## รายละเอียดเทคนิค
- ไฟล์ที่แก้: `src/App.tsx` (TabLayout + loader), `src/components/layout/BottomNavigation.tsx` (transition), `src/index.css` (keyframe ใหม่)
- ใช้ CSS animation/transition เท่านั้น ไม่เพิ่ม dependency
- ตรวจด้วย `npx tsgo --noEmit -p tsconfig.app.json` และ build ตามปกติ
