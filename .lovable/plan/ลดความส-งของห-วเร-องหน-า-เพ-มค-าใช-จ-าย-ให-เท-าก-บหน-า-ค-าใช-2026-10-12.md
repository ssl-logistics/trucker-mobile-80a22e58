# ลดความสูงของหัวเรื่องหน้า "เพิ่มค่าใช้จ่าย" ให้เท่ากับหน้า "ค่าใช้จ่าย"

## ปัญหา

แถบหัวเรื่องของหน้า "เพิ่มค่าใช้จ่าย" สูงกว่าหน้า "ค่าใช้จ่าย" ที่ใช้เป็นตัวอย่าง 11px (วัดจริง 87px เทียบกับ 76px) ทำให้ดูหนาและกินพื้นที่เกินจำเป็น

| หน้า | ความสูงแถบหัวเรื่อง (วัดจริง) |
| --- | --- |
| ค่าใช้จ่าย (ตัวอย่าง) | 76px |
| เพิ่มค่าใช้จ่าย | 87px |

## สิ่งที่จะปรับ

- ลดช่องว่างด้านบน-ล่างของแถบหัวเรื่องในหน้า "เพิ่มค่าใช้จ่าย" จาก 16px เหลือ 11px เพื่อให้สูง 76px เท่ากับหน้า "ค่าใช้จ่าย" พอดี
- ปุ่มย้อนกลับคงขนาดเดิม แตะง่ายเหมือนเดิม
- สี พื้นหลัง เส้นขอบ และตำแหน่งข้อความคงเดิมทั้งหมด (ไม่เปลี่ยนรูปแบบอย่างอื่น)
- หน้า "ค่าใช้จ่าย" ไม่แก้อะไร เพราะเป็นหน้าตัวอย่าง

## หลังแก้แล้ว

```text
ก่อน:   [ < ]  เพิ่มค่าใช้จ่าย     87px
หลัง:   [ < ]  เพิ่มค่าใช้จ่าย     76px  = เท่าหน้า "ค่าใช้จ่าย"
```

## รายละเอียดทางเทคนิค

- ไฟล์ที่แก้: `src/pages/AddExpensePage.tsx` บรรทัด 642
  - `className="px-4 py-4 flex items-center gap-3"` → `className="px-4 py-[11px] flex items-center gap-3"`
- ที่มาของเลข 76px: พื้นที่กันรอยแหว่งขอบจอ 14px (คลาส `.app-sticky-header` ใน `src/index.css` บรรทัด 290) + ปุ่มย้อนกลับ 40px + ช่องว่างบน-ล่าง 11×2 = 76px
- หน้าตัวอย่าง: `src/pages/JobExpensesPage.tsx` บรรทัด 473 ใช้ `px-4 py-6` + ปุ่ม `p-1` รวมเป็น 76px
- หมายเหตุ: ถ้าอยากได้ 78px (ค่าที่หลายหน้าในแอปใช้อยู่ เช่น `PlaceBidPage`) ให้ใช้ `py-3` แทน ต่างกัน 2px
- บนมือถือที่มีรอยแหว่งขอบจอ (notch) ระบบจะกันพื้นที่เพิ่มให้อัตโนมัติ หัวเรื่อง "เพิ่มค่าใช้จ่าย" จะไม่ทับรอยแหว่ง (หน้า "ค่าใช้จ่าย" ไม่มีส่วนนี้)
- ไม่แก้ข้อมูล ราคา หรือการคำนวณค่าใช้จ่ายใดๆ

## วิธีตรวจสอบ

1. วัดความสูงแถบหัวเรื่องทั้งสองหน้าด้วย Playwright ให้ได้ 76px เท่ากัน (ที่ 393×805)
2. วัดซ้ำที่ความสูงจอ 805 / 667 / 568px: หน้าจอยังไม่ต้องเลื่อน และแถบหัวเรื่องไม่บังปุ่ม "เพิ่มรายการ"
3. ตรวจ `build-errors.log` ว่าบิลด์ผ่าน
