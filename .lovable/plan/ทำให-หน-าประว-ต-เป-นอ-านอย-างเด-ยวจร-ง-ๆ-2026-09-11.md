# ทำให้หน้าประวัติเป็นอ่านอย่างเดียวจริง ๆ

## สาเหตุที่ยังกดเช็คอิน/อัปเดตสถานะได้

หน้าประวัติส่งสัญญาณ "มาจากประวัติ" (`?from=history`) ไปพร้อมกับลิงก์ แต่มีเพียงบางหน้าที่อ่านค่านี้:

- อ่านและปิดปุ่มแล้ว: หน้ารายละเอียดงาน, สรุปจุดรับ, สรุปตู้, จุดส่ง, ค่าใช้จ่ายของงาน
- ยังไม่อ่านเลย จึงยังกดยืนยันได้ตามปกติ:
  - หน้าเช็คอินตู้ (`ContainerCheckInPage`)
  - หน้าเช็คอินจุดรับ (`PickupDetailPage`)
  - หน้า SOP จุดรับ (`SOPCheckInPage`)
  - หน้า SOP ตู้ (`ContainerSOPPage`)
  - หน้า SOP จุดส่ง (`DeliverySOPCheckInPage`)
  - หน้าเพิ่มค่าใช้จ่าย (`AddExpensePage`)

นอกจากนี้ การ์ดงานประเภทที่กดจากบางแถวในหน้าประวัติ (แถวที่เปิดด้วยรหัสงานภายใน) นำทางไปโดยไม่ได้แนบ `?from=history` เลย ทำให้หน้าปลายทางเข้าใจว่าเป็นงานปัจจุบันและเปิดปุ่มทั้งหมด

## สิ่งที่จะทำ

1. เพิ่มตัวช่วยกลางตัวเดียวสำหรับอ่านสถานะ "มาจากประวัติ" โดยดูทั้งพารามิเตอร์ใน URL และค่าที่ส่งต่อมาทาง state เพื่อไม่ให้ค่าหายเมื่อเข้าหลายชั้น
2. ในทุกหน้าปฏิบัติงานข้างต้น: ซ่อนปุ่มยืนยัน/เช็คอิน/บันทึก และกันการกดส่งซ้ำ ให้เหลือแค่ดูข้อมูลและรูปที่บันทึกไว้แล้ว
3. แก้ลิงก์ในหน้าประวัติที่ยังไม่แนบ `?from=history` ให้แนบครบทุกเส้นทาง
4. ป้องกันเผื่อไว้ที่ระดับฟังก์ชันส่ง: ถ้าอยู่ในโหมดประวัติ ให้หยุดก่อนเรียก API พร้อมข้อความแจ้งว่างานนี้ปิดแล้ว
5. ค่าใช้จ่าย: ในโหมดประวัติดูรายการได้ แต่เพิ่ม/แก้/ลบไม่ได้ (ปิดหน้าเพิ่มค่าใช้จ่ายด้วย)

## ขอบเขต

- ไม่แตะฐานข้อมูล ไม่แตะฟังก์ชันฝั่งเซิร์ฟเวอร์
- หน้างานปัจจุบันยังทำงานได้เหมือนเดิมทุกอย่าง
- ใช้ได้ทั้งงานในประเทศและงานต่างประเทศ

## ตรวจสอบหลังแก้

เปิดงานจากหน้าประวัติทั้งงานในประเทศและต่างประเทศ แล้วไล่กดทุกจุด: เช็คอินจุดรับ, SOP, จุดส่ง, รับตู้/คืนตู้, ค่าใช้จ่าย ต้องเปิดดูได้แต่ไม่มีปุ่มยืนยันใด ๆ
