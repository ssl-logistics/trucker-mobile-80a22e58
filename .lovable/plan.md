# รองรับข้อมูลคิวจากทุกเส้นงาน (ธง "ดูคิวได้" จากระบบหลัก)

## สิ่งที่ยืนยันแล้ว (ตรวจโค้ดแล้ว)
- หน้างานปัจจุบันรวมงานจาก 4 เส้น: `get-freelance-accepted-jobs`, `get-factory-assigned-jobs`, `list-tickets`, `get-driver-assigned-jobs`
- ทุกจุดรวมงานใช้การส่งผ่านทุกช่อง (spread) — ช่องใหม่จาก API ไหลถึงการ์ดอัตโนมัติ
- `list-tickets` เป็นตัวกลางของแอปที่ส่งต่อผลตอบจากระบบหลักแบบไม่เปลี่ยนแปลง
- `getQueueInfo` ใน `CurrentJobsPage.tsx` อ่านช่องคิว: `has_queue`, `queue_data.{my_queue|queue_number, current_queue, remaining_queues}`, `queue_number`, `current_queue`, `remaining_queues`, `queue_estimated_time`

## สิ่งที่จะทำ (UI เท่านั้น — ไม่แตะวิธีดึงข้อมูล)
1. **ธง "ดูคิวได้" แบบยืดหยุ่น** — เพิ่มการตรวจจับใน `getQueueInfo` รองรับชื่อธงที่พบบ่อย:
   `can_view_queue`, `has_queue`, `queue_available` (ค่า true) และ `queue_data` ที่ส่งมาเป็นข้อความ JSON ให้แปลงเป็นออบเจ็กต์ก่อนใช้
2. **เงื่อนไขปุ่ม** — แสดงปุ่มคิวเมื่อ: มีธงดูคิวได้ หรือมีข้อมูลคิวจริง (ช่องเดิม) — งานที่ไม่มีทั้งสองแบบยังแสดงปุ่มดูข้อมูลงานเต็มความกว้างปุ่มเดียว
3. **ค่าที่แสดง** — ใช้ข้อมูลจริงจาก `queue_data` เมื่อส่งมา ถ้าธงบอกว่าดูคิวได้แต่ยังไม่ส่งตัวเลข ใช้ค่าตัวอย่างเดิม (คิว 0015 / Q012 / เหลือ 2 คิว / เวลาตัวอย่าง) จนกว่าระบบหลักส่งค่าจริง
4. ใช้ผลกับงานจากทั้ง 4 เส้น (ฟรีแลนซ์ + งานโรงงาน + งานชนะประมูล + คนขับบริษัท/ภายนอก) เพราะตรวจที่จุดเดียวก่อนวาดการ์ด
5. ป๊อปอัปคิวและหัวข้อภาษา (4 ภาษา) มีอยู่แล้ว — ไม่แตะ

## ไฟล์ที่แก้
- `src/pages/CurrentJobsPage.tsx` — ฟังก์ชัน `getQueueInfo` (จุดเดียว)

## ไม่ได้ทำ
- ไม่แตะ Edge Functions หรือเส้น API — ข้อมูลคิวรอรับจากระบบหลัก
- ไม่อัปเดตคิวแบบเรียลไทม์ / ไม่เพิ่มการยิงเส้นใหม่
