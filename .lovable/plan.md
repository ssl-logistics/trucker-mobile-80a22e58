# แก้งานต่างประเทศ "จุดส่งหาย" (DEMO-BK-0010)

## สาเหตุ (ตรวจสอบจาก API จริงแล้ว)

ดึงข้อมูลงาน `OR20260924001/02` (คนขับ b3000001-…-0001) จาก API พบว่า:

```text
job_type   = "bl"              -> เป็นงานขาเข้า
bl_no      = "DEMO-BK-0010"
booking_no = "DEMO-BK-0010"    <- ซ้ำค่าเดียวกัน (ควรมีอย่างใดอย่างหนึ่ง)
cargo_point = DEMO CARGO POINT AYUTTHAYA (มีพิกัด/ที่อยู่/ผู้ติดต่อครบ)
destinations = []
return_terminal = ลานคืนตู้บางพลี (เดโม)
```

หน้ารายละเอียดงานตัดสินทิศทางงานจาก "มี bl_no หรือ booking_no" ไม่ได้ดูจาก `job_type`:

- มี `bl_no` -> ซ่อนการ์ด "จุดรับสินค้า"
- มี `booking_no` -> ซ่อนการ์ด "จุดส่งสินค้า" (destinations ที่สร้างจาก cargo_point)

พองานนี้ส่งมาทั้งสองค่า จึงถูกซ่อน **ทั้งจุดรับสินค้าและจุดส่งสินค้า** เหลือแค่ 2 การ์ด
(จุดรับตู้ + จุดคืนตู้) และหัวข้อขึ้นเป็น "Booking … (ขาออก)" ทั้งที่จริงเป็นงานขาเข้า

## สิ่งที่จะแก้

1. **ทำให้ทิศทางงานชัดเจนที่ชั้น map ข้อมูล** (`src/pages/JobDetailPage.tsx`)
   - เพิ่มการ normalize: ถ้าได้ทั้ง `bl_no` และ `booking_no` (โดยเฉพาะค่าซ้ำกัน)
     ให้ยึด `job_type` เป็นตัวตัดสิน — `bl` -> เก็บเฉพาะ `bl_no`, `booking`/`export` -> เก็บเฉพาะ `booking_no`
   - ถ้า `job_type` ไม่ชี้ชัด ให้ยึด `bl_no` เมื่อมี `return_terminal` + จุดรับเป็นท่าเรือ (ขาเข้า)
2. **ให้จุดส่งของงานขาเข้ามาจาก cargo_point เสมอ**
   - ปัจจุบันมี fallback สร้าง destination จาก `sender_*`/`destination_*` อยู่แล้ว
     แต่ต้องมั่นใจว่าใช้ `cargo_point` (ชื่อ/ที่อยู่/พิกัด/ผู้ติดต่อ/วันเวลา) เป็นหลักเมื่อ `destinations` ว่าง
3. **จุดที่ map ข้อมูลงานที่อื่นให้ normalize เหมือนกัน**
   - `src/pages/ContainerCheckInPage.tsx` และจุดที่ส่ง `location.state.jobData` ต่อ
     เพื่อให้ flow เช็คอิน/คืนตู้ไม่สับสนทิศทาง

ผลลัพธ์ที่คาดหวังสำหรับงานนี้: แสดง 3 จุด — จุดรับตู้หนัก (ท่าเรือ) -> จุดส่งสินค้า
(DEMO CARGO POINT AYUTTHAYA) -> จุดคืนตู้เปล่า (ลานคืนตู้บางพลี) และหัวข้อขึ้น
"BL : DEMO-BK-0010 (ขาเข้า)"

## ไม่แตะ

- UI/ดีไซน์การ์ดเดิม ใช้เหมือนเดิมทั้งหมด
- Logic งานในประเทศ และงานต่างประเทศที่ส่งมาถูกต้องอยู่แล้ว (มีค่าเดียว)
- ไม่แก้ฝั่ง API ภายนอก (แต่แนะนำแจ้งทีมหลังบ้านว่าไม่ควรส่ง bl_no/booking_no ซ้ำกัน)
