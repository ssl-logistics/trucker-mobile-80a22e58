# แผน: เมนู "เอกสาร" — ดึงเอกสารให้ได้อีกครั้ง + แสดง "ไม่มีเอกสาร" เมื่อไม่มี

## สรุปสั้น

ตอนนี้งาน `OR20260910068` มีลายเซ็นอยู่จริง 4 รายการ (รับของ 1, ส่งของ 3 จุด) แต่หน้าตางเอกสารขึ้น "โหลดเอกสารไม่สำเร็จ กรุณาลองใหม่" เพราะวิธีเรียกที่ใช้อยู่ (ฟังก์ชันสำรองของระบบ) ล้มเหลวตั้งแต่ก่อนคำขอถูกส่งออกไป — โค้ดเดิมของโปรเจกต์มีบันทึกไว้อยู่แล้วว่าวิธีนี้ใช้ไม่ได้กับระบบล็อกอินแบบของแอปนี้ จะเปลี่ยนไปเรียกตรงแบบเดียวกับที่ฟีเจอร์อื่นที่ใช้อยู่ใช

และเมื่อ งานนั้นไม่มีเอกสารจริงๆ (หรือยังไม่ถูกบันทึกในระบบ) จะแสดงข้อความ "ไม่มีเอกสาร" แทนที่จะขึ้น error ว่าโหลดไม่สำเร็จ

## สิ่งที่ทำ

### 1. ทำให้ดึงเอกสารกลับมาแสดงได้
- ในหน้าตางเอกสาร เปลี่ยนวิธีเรียกตัวกลางดึงเอกสาร จากการเรียกผ่านฟังก์ชันสำรองของระบบ มาเป็นการเรียกตรงไปหาตัวกลาง (endpoint `get-order-documents`) พร้อมคีย์ประจำแอปในหัวคำขอ เหมือนที่ฟีเจอร์ GPS / ค่า Google Maps ทำอยู่
- ผลที่ได้: เปิดเมนู "เอกสาร" แล้วเห็นรายการลายเซ็น/เอกสาร/ไฟล์ B/L จริงของงานนั้น ไม่ใช่หน้า error

### 2. แสดง "ไม่มีเอกสาร" เมื่อไม่มีเอกสาร
- ถ้าตัวกลางตอบว่า "ไม่พบงานขนส่ง" หรือพบแต่งานแต่ไม่มีรายการใดๆ (ลายเซ็น = 0, เอกสารคนขับ = 0, ไฟล์ B/L = ไม่มี) → แสดง "ไม่มีเอกสาร" พร้อมไอคอนกลางหมวด "เอกสารที่แนบแล้ว"
- ถ้าเป็นความล้มเหลวจริง (เน็ตหลุด, เซิร์ฟเวอร์ตอบผิด, คีย์ผิด) → ยังแสดง "โหลดเอกสารไม่สำเร็จ กรุณาลองใหม่" + ปุ่มลองใหม่ เหมือนเดิม

### 3. ใช้ได้ทั้งหน้างานปัจจุบันและหน้าประวัติ
- หน้าประวัติ (โหมดดูอย่างเดียว) แสดง "ไม่มีเอกสาร" เช่นกัน และยังคงไม่แสดงฟอร์มแนบไฟล์ใหม่
- หน้างานปัจจุบัน: แสดง "ไม่มีเอกสาร" ในหมวดดู พร้อมฟอร์มแนบเอกสารตามเดิม (ไม่แตะฟอร์มแนบ)

### 4. ข้อความใหม่ 4 ภาษา (ไทย/อังกฤษ/เกาหลี/จีน)
- เพิ่มคำว่า "ไม่มีเอกสาร" สำหรับหมวดนี้ (ไทย: "ไม่มีเอกสาร", อังกฤษ: "No documents", เกาหลี: "문서가 없습니다", จีน: "没有文档")
- ข้อความ "ยังไม่ได้แนบเอกสาร" เดิมจะไม่เอามาใช้กับหมวดดูอีก เพราะสื่อความหมายคนละอย่าง

## ผลต่อผู้ใช้งาน
- เปิดเมนู "เอกสาร" ในงานที่มีลายเซ็นแล้ว จะเห็นลายเซ็นจริง กดดูเต็มจอได้
- งานที่ยังไม่มีเอกสาร จะเห็นคำว่า "ไม่มีเอกสาร" ชัดเจน แทนข้อความ error ที่ทำให้เข้าใจว่าแอปพัง
- การแนบเอกสารใหม่ยังทำงานเหมือนเดิมทุกประการ (ฟอร์มเดิม, จำกัด 10 ไฟล์, JPG/PNG/WEBP/HEIC/PDF)
- ฝั่งแอปที่ติดตั้งในเครื่อง: ต้อง build + sync ใหม่จึงเห็นการเปลี่ยนแปลงนี้

## รายละเอียดเทคนิค

- ไฟล์ที่แก้: `src/components/job/JobDocumentsSheet.tsx` (ฟังก์ชัน `fetchDocuments` + ส่วนแสดงผลหมวด "เอกสารที่แนบแล้ว"), `src/contexts/LanguageContext.tsx` (เพิ่มคีย์ `docs.none` ทั้ง 4 ภาษา)
- `fetchDocuments` จะใช้ `fetch` ตรงไป `${VITE_SUPABASE_URL}/functions/v1/get-order-documents` แบบ POST JSON `{ order_number }` พร้อมหัวคำขอ `apikey` + `Content-Type` (รูปแบบเดียวกับ `src/lib/trackingRoomClient.ts` และ `src/hooks/useGpsTracking.ts` ที่ใช้อยู่แล้ว) แทน `supabase.functions.invoke` ที่ล้มเหลวที่ชั้น auth ก่อนส่งคำขอจริง (บันทึกของโปรเจกต์: `src/lib/trackingRoomClient.ts:1-7`)
- การแยกสถานะ: `200` = มีข้อมูล, `404 (found=false)` = ไม่มีเอกสาร, อื่นๆ = error ให้ลองใหม่ — เพิ่ม state `docsEmpty` แยกจาก `docsError` เพื่อไม่ให้ "ไม่มีเอกสาร" ถูกมองว่าเป็นความล้มเหลว
- ตัวกลาง `get-order-documents` ที่ deploy ไว้แล้วไม่ต้องแก้: ทดสอบยิงตรงด้วยคีย์ประจำแอปอย่างเดียวแล้วตอบ 200 พร้อมลายเซ็น 4 รายการของ `OR20260910068` และตอบ 404 เมื่อเลขงานไม่มีจริง (เช่น `OR20260910068/03`) — ไม่ต้องใส่ token ล็อกอิน และไม่ต้องแตะ `supabase/config.toml`
- ไม่แตะ: ฟอร์มแนบเอกสาร (`driver-documents` POST), flow เช็คอิน/SOP/POD, QTruck, การเงิน
- ตรวจสอบ: ทดสอบในเบราว์เซอร์จริงว่าเปิดเมนูแล้วเห็นลายเซ็น 4 รายการของ `OR20260910068`, งานที่ไม่มีเอกสารขึ้น "ไม่มีเอกสาร", และลองกับเลขงานที่ไม่มีในระบบ; ตรวจ build ผ่าน
