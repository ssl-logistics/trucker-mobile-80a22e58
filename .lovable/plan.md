# ทำแคชให้หน้าประวัติงาน ไม่ต้องดึงใหม่ทุกครั้ง

## สาเหตุที่ตรวจพบ

หน้าประวัติ (`JobHistoryPage.tsx`) ไม่มีแคชเลย — ทุกครั้งที่เปิดหน้าจะยิง API ใหม่ทั้งหมด:
- คนขับบริษัท/ภายนอก: ยิง `get-driver-assigned-jobs` 12 สถานะ + `get-driver-checkins` พร้อมกัน
- ฟรีแลนซ์: ยิง `get-freelance-accepted-jobs` + `get-factory-assigned-jobs` + `get-driver-checkins` + `list-tickets` พร้อมกัน
- แยกยิง `job_applications` จากฐานข้อมูลของเราอีกเส้น

ส่วนหน้างานปัจจุบันมีแคชอยู่แล้ว (`current_jobs_cache_v1_<รหัสคนขับ>`) — เปิดหน้าแสดงรายการที่จำไว้ทันที แล้วค่อยยิง API อัปเดตเบื้องหลัง

## สิ่งที่จะทำ (ใช้รูปแบบเดียวกับหน้างานปัจจุบัน)

1. **เพิ่มแคชหน้าประวัติ** ใน `JobHistoryPage.tsx`:
   - คีย์ `job_history_cache_v1_<รหัสคนขับ>` เก็บรายการงานที่จบแล้ว (completedJobs)
   - คีย์ `job_history_apps_cache_v1_<รหัสคนขับ>` เก็บรายการ job_applications
2. **เปิดหน้า**: อ่านแคชขึ้นมาแสดงทันที (ไม่ต้องรอโหลด/ไม่มีจอว่าง) แล้วค่อยยิง API เบื้องหลัง
3. **เมื่อ API ตอบกลับ**: อัปเดตรายการบนจอ + เขียนกลับทับแคช — ครั้งต่อไปเปิดจะเห็นข้อมูลล่าสุดทันที
4. **กรณีไม่มีแคช** (ครั้งแรก): แสดงตัวโหลดเหมือนเดิมจนข้อมูลมา
5. **กรณี API ล้มเหลว**: ถ้ามีแคชให้แสดงแคชต่อ ไม่ล้างจอเป็นว่าง

## ขอบเขต

- แก้เฉพาะ `src/pages/JobHistoryPage.tsx` — ไม่แตะเส้น API, ไม่แตะหน้าอื่น
- ตัวกรองเดือน/แท็บ/แบ่งหน้า ทำงานบนข้อมูลชุดเดิม ไม่เปลี่ยน
- โหมดอ่านอย่างเดียวของหน้าประวัติคงเดิมทุกอย่าง

## ตรวจสอบหลังแก้

- เปิดหน้าประวัติครั้งแรก → โหลดปกติ; ออกแล้วเปิดใหม่ → รายการขึ้นทันทีจากแคช
- งานที่เพิ่งจบใหม่ยังโผล่หลัง API ตอบกลับเบื้องหลัง
- typecheck ผ่าน และ build OK
