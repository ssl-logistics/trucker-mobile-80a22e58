# แก้หน้ารายละเอียดจุดส่งในประวัติให้เป็น Read-only

## สาเหตุที่ยืนยันแล้ว
หน้า `DeliveryDetailPage` รับรู้ `?from=history` ได้ถูกต้อง แต่ปุ่ม “เช็คอิน” แสดงด้วยเงื่อนไขเพียงว่ายังไม่เคยเช็คอิน (`!isCheckedIn`) โดยไม่ได้ตรวจโหมดประวัติ และฟังก์ชันยืนยันเช็คอินก็ไม่มีตัวป้องกันก่อนเรียก API จึงยังอัปเดตงานจากหน้าประวัติได้

## การแก้ไข
- ซ่อนปุ่ม “เช็คอิน” เมื่อเปิดจุดส่งจากหน้าประวัติ
- ปิดทางเรียกคำสั่งเช็คอินซ้ำที่ระดับฟังก์ชัน เพื่อไม่ให้ส่ง API แม้มีการเปิดกล่องยืนยันค้างไว้หรือเรียกผ่านทางอื่น
- ใส่ตัวป้องกันแบบเดียวกันให้คำสั่งที่แก้ข้อมูลในหน้านี้ ได้แก่ ยืนยัน POD/ชำระเงิน เพื่อให้หน้า Delivery ในประวัติเป็นดูอย่างเดียวจริง
- คงการแสดงข้อมูล รูป และสถานะเดิมทั้งหมด และไม่เปลี่ยนพฤติกรรมของงานใน “งานปัจจุบัน”

## การตรวจสอบ
- เปิดออเดอร์ `OR20260812003/03` จากหน้าประวัติที่จุดส่งซึ่งยังไม่เช็คอิน และยืนยันว่าไม่มีปุ่มหรือกล่องยืนยันที่อัปเดตสถานะได้
- ตรวจเส้นทางย้อนกลับว่ายังกลับไปหน้าประวัติ
- เปิดงานที่ยังดำเนินการจาก “งานปัจจุบัน” และยืนยันว่าปุ่มเช็คอินยังทำงานตามเดิม
- ตรวจผลการประกอบแอปและข้อผิดพลาดหน้าใช้งานหลังแก้
