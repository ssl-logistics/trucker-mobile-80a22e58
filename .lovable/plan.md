# ทำให้หน้างานปัจจุบันโหลดเร็วขึ้น

## สาเหตุที่พบในโค้ด
1. **ฟรีแลนซ์:** หลังได้รายการงานแล้ว แอปยังค้าง "กำลังโหลด..." ต่อ เพราะรอสร้างห้องติดตามของงานประมูลที่ชนะทีละงาน (รวมรอ GPS ได้สูงสุด 10 วินาทีต่องาน) ก่อนปิดตัวโหลด
2. **คนขับบริษัท/ภายนอก:** แอปดึงเช็คอินของคนขับทุกคนแยกทีละงาน สำหรับทุกงานที่ได้มา (สูงสุด 100 งาน รวมงานที่ปิดแล้ว) และต้องรอครบทุกงานก่อนแสดงผล

## สิ่งที่จะแก้
1. ปิดตัวโหลดและแสดงรายการงานทันทีที่ได้ข้อมูล ส่วนการสร้างห้องติดตามงานประมูลย้ายไปทำเบื้องหลัง (ไม่ขวางหน้าจอ) และทำพร้อมกันแทนทีละงาน
   - ไม่กระทบการทำงานอื่น: รายการงาน/สถานะไม่ได้ใช้ห้องติดตาม และระบบสร้างห้องกันการสร้างซ้ำอยู่แล้ว
   - เพิ่มตัวกันไม่ให้สร้างห้องของงานเดียวกันซ้อนกัน เมื่อผู้ใช้ดึงรีเฟรชหน้าระหว่างที่ยังสร้างไม่เสร็จ
2. ดึงเช็คอินของคนขับทุกคนเฉพาะงานที่ยังจำเป็นต้องตรวจ (ไม่รวมงานที่สถานะ completed/closed/container_returned แล้ว) และจำกัดจำนวนที่ยิงพร้อมกัน
3. จำรายการงานล่าสุดไว้ในเครื่อง: เปิดหน้าอีกครั้งจะแสดงรายการเดิมทันที แล้วอัปเดตเบื้องหลัง (แสดงตัวโหลดเต็มเฉพาะครั้งแรก)

กฎการกรองงานที่เสร็จ/โอนงาน ไม่เปลี่ยน

## รายละเอียดทางเทคนิค
- `src/pages/CurrentJobsPage.tsx`
  - freelance: `setLoading(false)` ทันทีหลัง `setAcceptedJobs(normalizedJobs)`; ห่อ loop bid-job tracking เป็น `void Promise.allSettled(...)` (GPS `maximumAge` 60s, timeout 5s)
  - internal/external: filter `apiJobs` ที่สถานะไม่ใช่ terminal ก่อนเรียก `getDriverCheckins(..., { allDrivers: true })`, concurrency ครั้งละ 5
  - cache `current_jobs_cache_v1_<driverId>` ใน localStorage: อ่านตอน mount → set jobs + loading=false ถ้ามี; เขียนหลังโหลดสำเร็จ
- ตรวจด้วย Playwright จับเวลาก่อน/หลังจนรายการขึ้น
