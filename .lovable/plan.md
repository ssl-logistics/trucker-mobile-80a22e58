# ตรวจและแก้ปัญหาแจ้งเตือนไม่ขึ้น

## สิ่งที่ตรวจพบแล้ว
- ระบบยังสร้างแจ้งเตือน "งานใหม่" ในแอปได้ — วันนี้มี 4 รายการ (ล่าสุด 13:19 น. เวลาไทย) ให้คนขับ 2 คน
- แจ้งเตือนประเภทอื่น (คิว QTruck, สถานะงาน, กำหนดคืนตู้, closing) **ไม่มีเลยใน 3 วันที่ผ่านมา**
- ระบบส่ง push ขึ้นมือถือ **ไม่ถูกเรียกเลย** ในบันทึกที่ดูได้ ทั้งที่คนขับที่ได้แจ้งเตือนวันนี้ลงทะเบียนรับ push ไว้แล้ว → แจ้งเตือนอยู่แค่ในหน้าแจ้งเตือน ไม่เด้งขึ้นเครื่อง
- บัญชีที่ทดสอบอยู่ (d2000002…) ได้ "0 งานใหม่" เพราะ 13 งานที่มีวันรับของผ่านไปแล้วหรือเคยแจ้งไปแล้ว — เป็นไปตามเงื่อนไขเดิม

สาเหตุที่ push ไม่ถูกส่งยังไม่ยืนยัน ต้องตรวจขั้นแรกก่อนแก้

## ขั้นตอน
1. **ยืนยันสาเหตุ**: ยิงทดสอบระบบส่ง push ตรงๆ ให้บัญชีทดสอบ และอ่านบันทึกของตัวส่งงานใหม่ / รับสถานะงาน / QTruck ว่าเรียก push แล้วได้ผลอะไร (เรียกไม่ถึง, ถูกปฏิเสธสิทธิ์, หรือส่งไป Google/Apple ไม่สำเร็จ)
2. **แก้ตามสาเหตุที่พบ** เช่น ตัวส่ง push ไม่ได้เปิดใช้งาน → เปิดใหม่; รหัสระหว่างระบบไม่ตรง → ปรับให้ตรวจผ่าน; ส่งไป Google/Apple ไม่สำเร็จ → แก้ค่าเชื่อมต่อ
3. **บันทึกผลการส่ง push** ในตัวเรียกทุกจุด (สถานะตอบกลับ) เพื่อให้ครั้งหน้าดูสาเหตุได้ทันที
4. **ตรวจแจ้งเตือนประเภทอื่น** ว่าทำไม 3 วันไม่มีเลย (ไม่มีเหตุการณ์จริง หรือสร้างไม่สำเร็จ)
5. ทดสอบจริง: ส่งแจ้งเตือนทดสอบให้บัญชีทดสอบ ยืนยันว่ามีรายการในหน้าแจ้งเตือนและ push ถูกส่งสำเร็จ

## ไม่แตะ
- เงื่อนไขงานใหม่เดิม (แจ้งครั้งเดียวต่อออเดอร์, ข้ามงานวันรับของผ่านไปแล้ว)
- flow เช็คอิน/SOP/POD, การเงิน, เมนูเอกสาร

## รายละเอียดทางเทคนิค
- `check-new-jobs` เรียก `send-push-notification` เฉพาะเมื่อมี push_subscriptions และไม่ตรวจ response; `function_edge_logs` 7 วันไม่มี request ไป `send-push-notification` เลย
- `send-push-notification` ตรวจ Bearer = SUPABASE_SERVICE_ROLE_KEY หรือ x-app-secret — ถ้า key ฝั่งผู้เรียกไม่ตรงจะได้ 401
- เพิ่ม log `status` + body ของ push response ใน check-new-jobs, receive, receive-job-status, qtruck-webhook
